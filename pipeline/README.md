# Дереккөз құбыры (pipeline) — жоспар және құралдар

Мақсат: ұлттық кітапхана мен басқа қорлардағы **кітап скандарын** зерттеуге жарамды,
дереккөзі көрсетілген мәтінге айналдыру.

> **Ескерту.** Бұл бума әлі толық жұмыс істемейді. Жұмыс істейтіні —
> `normalize/kaz_lint.py`. Қалғаны — жоспар мен қаңқа. Сынақтан өтпеген код
> жазылмады: сайттың нақты құрылымын көрмей селектор жазу — жалған жұмыс.

---

## 1. Алдымен тексерілген екі нәрсе

### 1.1. Кітапханада API бар ма?

**Жоқ** (құжатталған түрде). [kazneb.kz](https://kazneb.kz/kk/about) — Қазақстанның
ұлттық электрондық кітапханасы, **72 601 PDF** құжат бар, қазақ, орыс, ағылшын
тілдерінде. Ашық API туралы құжаттама табылмады; қолжетімділік «қолданыстағы
заңнама аясында» деп берілген.

**Салдары:** парсер жазар алдында үш нәрсені істеу керек — `robots.txt` пен
пайдалану шарттарын оқу, ал одан да дұрысы — **кітапханаға ресми хат жазып,
зерттеу мақсатында топтама алуды сұрау**. Ұлттық кітапханалар ғылыми жобаға жиі
рұқсат береді, әрі бұл парсер жазудан **жылдамырақ та, қауіпсіз де**.

### 1.2. Дайын қазақ модельдері көмектесе ме?

ISSAI (Nazarbayev University) қорындағы 37 модель мен 74 деректер жинағы
тексерілді: `models.md`. Қысқаша — **ең қиын мәселені шешпейді**: араб
графикасына (төте жазу) арналған модель де, деректер жинағы да жоқ.
Бірақ **аудио арнасы** күтпеген жол ашады (§6.1).

### 1.3. Қазақ тіліне OCR сапасы қандай?

Мұнда күтпеген нәрсе шықты. Соңғы зерттеулер бойынша:

| Жазу түрі | CER (таңба қатесі) | Баға |
|---|---|---|
| **Кириллица** (қазіргі басылымдар) | ~5,3% (қазіргі мультимодалды модельдер) | Жақсы |
| **Латын** | ~26,4% | Нашар |
| **Араб жазуы — төте жазу** | **~35,5%** | Өте нашар |

Кириллица үшін Tesseract-тің `kaz.traineddata` базасы да жеткілікті деңгейде
жұмыс істейді, оған post-OCR түзету аз ғана пайда береді.

**Мұның біз үшін мәні үлкен әрі жағымсыз.** Біздің шешілмеген сұрақтарымыз
(T-6 — Үмбетей мәтінінің қолжазба нұсқасы; Мәшһүр Жүсіп жазбалары) дәл **төте
жазудағы** дереккөздерде жатыр — яғни OCR ең нашар істейтін жерде.

**Салдары:** құбыр екі бөлек арнаға бөлінеді:
- **А арнасы (кириллица):** автоматтандыруға болады, OCR + тексеру жеткілікті.
- **Б арнасы (төте жазу):** автоматтандыруға **болмайды**. Мұнда OCR тек көмекші —
  әр бет адам тексеруінен өтеді. Жоспарлағанда бұған уақыт бөлу керек.

## 2. Ең маңызды сәулет шешімі: авторлық құқық

Репозиторий **ашық**. Ал скандардың басым бөлігі — авторлық құқықпен қорғалған
басылымдар («Бес ғасыр жырлайды», 1989 — соның бірі).

Сондықтан құбыр деректі **екіге бөліп** сақтайды:

```
raw/          ← .gitignore ішінде. Жүктелген PDF, бет суреттері, толық OCR мәтіні.
              Тек жергілікті машинада. Репозиторийге ЕШҚАШАН кірмейді.
derived/      ← репозиторийге кіреді. Дәйексөз (қысқа), метадерек, бет нөмірі,
              біздің талдауымыз, тексеру нәтижесі.
```

Бұл — заңдық қана емес, **әдіснамалық** шешім де: біздің жұмысымыз мәтінді қайта
жариялау емес, **тұжырымдарды тексеру**. Ал тексеру үшін толық кітап емес, дәл
сілтеме мен қысқа дәйексөз керек.

**Ерекшелік:** авторлық құқық мерзімі өткен (XIX ғ. – XX ғ. басы) басылымдар мен
қолжазбаларды толық сақтауға болады.

## 3. Құбыр сатылары

```
[1] Нысан тізілімі        sources.yaml — қай қор, қандай кітап, қандай рұқсат
        ↓
[2] Алу (fetch)           HTTP → PDF. Selenium тек JS-қа жабылған көрсеткіште
        ↓
[3] Бетке бөлу            PDF → бет суреттері (pdftoppm), 300+ dpi
        ↓
[4] OCR                   А арнасы: автомат.  Б арнасы: OCR + адам тексеруі
        ↓
[5] Түзету (normalize)    kaz_lint.py + аралас жазу, тасымал, тыныс белгі
        ↓
[6] Сегменттеу            кітап → шығарма → шумақ. Метадерек бекітіледі
        ↓
[7] Сақтау (store)        derived/ ішіне: мәтін + паспорт + бет сілтемесі
        ↓
[8] Салғастыру            variant_diff — қолда бар нұсқамен айырманы шығару
```

**Ең құнды саты — [8].** Ол репозиторийдегі `zertteu/tekseru/matin-nusqalary.md`
жұмысын автоматтандырады: жаңа тапқан нұсқаны бұрынғысымен салыстырып, есім
бұрмалануын, топоним айырмасын, жол қосылу-түсуін кестеге шығарады.

## 4. Метадерек — құбырдың өзегі

Әр сақталған мәтін біздің паспорт өрістерін алып жүреді. Схема:
`schema/document.yaml`. Бұл кездейсоқ емес: біздің бүкіл әдістемеміз «бұл дерек
қайдан?» деген сұраққа жауап бере алуға негізделген. Дереккөзі жоғалған мәтіннің
құны нөлге тең — ол V деңгейге түседі.

Міндетті өрістер: `source_id`, `edition`, `page`, `scan_url`, `ocr_engine`,
`ocr_confidence`, `human_verified`, `level` (I–V), `retrieved_at`.

## 5. Selenium керек пе?

**Әдетте — жоқ.** Реті:

1. Тікелей PDF сілтемесі бар ма? → `requests` жеткілікті.
2. Бет статикалық HTML ме? → `requests` + `BeautifulSoup`.
3. Көрсеткіш JS-пен бет-бет жүктей ме? → сол JS шақыратын **ішкі API-ды** тап
   (браузер Network қойындысы). Әдетте ол JSON қайтарады — Selenium қажет емес.
4. Тек сонда ғана → Playwright (Selenium-нан жеңіл әрі тұрақтырақ).

Selenium — ең соңғы амал: баяу, сынғыш, серверге салмақ түсіреді.

**Әр жағдайда:** `robots.txt` сақтау, сұраныс аралығы (кемінде 1–2 сек),
`User-Agent` ішінде байланыс деректерін көрсету, түнде жүктеу.

## 6. Қазір не жұмыс істейді

### 6.1. Аудио арна — ISSAI стегінен шыққан жаңа жол

`Qolda-AVL` модельдері Whisper негізіндегі қазақ ASR тармағын алып жүреді, ал
ISSAI-де `Kazakh_Speech_Corpus_2` жинағы бар. Демек **күй аңыздары мен жыраулық
орындау жазбаларын** мәтінге түсіру — скан парсерінен бөлек, өз алдына арна.
Ол `derekter/kuiler/` бос бумасын толтыруға тікелей жол. Толығы: `models.md`, §3.2.

### `eval/` — KazNERD сынағы, **нақты жүргізілген**

KazNERD моделі біздің жыр корпусында сыналды: **PER Recall 92%**, Precision ~50–60%.
Кандидат генераторы ретінде жарайды. Colab дәптері бар — компьютерді жүктемейді.
Толығы: `eval/README.md`.

Сынақтың басты сабағы: бірінші жүргізгенде нәтиже 18% болып шыққан еді, себебі
модель емес, **агрегация баптауы** қате таңдалған. «Модель нашар» деген
қорытындының өзін тексеру керек екен.

### `normalize/kaz_lint.py` — дайын, сыналған

Аралас жазуды (латын ↔ кириллица бір сөзде) табады. Бұл — OCR-дың ең жиі әрі
**көзге көрінбейтін** қатесі.

```bash
python3 pipeline/normalize/kaz_lint.py derekter/*/*.md
```

Репозиторийде сынағанда **3 нақты қате тапты**:
- `er-zhanibek-anyzy.md` — «Cоғыста» (латын C) — аңыз мәтініндегі түпнұсқа қате;
- `zhyraular-tizimi.md` — «бетi» (латын i) — біздің өз файлымыздағы қате, түзетілді.

Неге маңызды: «Cоғыста» көзге «Соғыста» болып көрінеді, бірақ іздеу оны таппайды.
Мыңдаған беттік OCR корпусында мұндай қате жүздеп кездеседі.

**Әдейі алынып тасталған ереже:** «қайталанған буын». Қазақ жалғауы табиғи түрде
буын қайталайды («Шамамен», «заманының»), сондықтан ол тек жалған дабыл берді.
Бұл — эвристиканың шегін көрсететін сабақ: мұндай қатені табу үшін сөздік керек.

## 7. Келесі қадамдар (кезектілігі бойынша)

1. **Кітапханаға ресми хат** — парсер жазудан бұрын. Ең арзан жол.
2. `sources.yaml` толтыру — қай кітап нақты керек (тізім §8-де).
3. Бір кітапқа қолмен толық цикл жүргізу — құбыр жарамды ма, сонда көрінеді.
4. `variant_diff` жазу — салғастыру құралы.
5. Тек содан кейін автоматтандыру.

**Ұсыныс:** алдымен бір ғана кітапты толық өткізіңіз. Құбырды бүкіл қорға
жоспарлап, содан кейін бірінші кітапта тұрып қалу — жиі кездесетін қате.
