# Тұлғалар тізілімі

Жобаның **үшінші тармағы**. Алдыңғы екеуі тақырыптық еді, бұл — **құрылымдық**.

| Тармақ | Сұрағы |
|---|---|
| 1. Батырлар (`zertteu/tekseru/`) | Бес тұлға туралы не білеміз? |
| 2. Бала әлемі (`zertteu/bala-alemi/`) | Бала қалай өмір сүрді? |
| **3. Тізілім (осы бума)** | **Қанша тұлға бар, кімнің өз жырауы болды?** |

## Не үшін

Бұрынғы құрылымда тұжырымдар бар еді, ал **тұлға жазбасы** жоқ болатын.
«Қабанбай туралы, деңгейі A, түпнұсқадан оқылған бәрін көрсет» деген сұрақ
grep-пен ғана шешілетін. Тізілім соны түзетеді.

Схема: **`00-shema.md`** — міндетті түрде алдымен оқылады.

## Басты сұрақ: «өз жырауы» деген не

Схеманың §2-сіндегі типология бүкіл тізілімнің өзегі:

| Тип | Мәні |
|---|---|
| **З** | Жырау батырмен **бір дәуірде**, оқиғаның куәгері |
| **К** | Кейінгі буын жыршысы |
| **Э** | Атаулы айтушысы жоқ, эпос қана |
| **Ж** | Ештеңе табылмады |
| **Д** | Атрибуциясы дауда |

**Тек З типі ғана «өз жырауы болды» дегенді білдіреді.** Қалғаны — басқа
нәрсе, әрі дерек күші де басқа.

Бұл — жобаның ең басынан келе жатқан қағида: Үмбетей Бөгенбайдың өлер сәтінде
қасында болған, сондықтан оның жыры **I деңгей**. Ал кейінгі ғасырда шығарылған
жыр — қанша көркем болса да, **II деңгей**.

## Міндетті ереже — мінез бен қасиет

Схеманың §4-і: «күші мол», «айлакер», «батыл» деген сөздер **ешқашан факт
ретінде жазылмайды**. Әрқашан: *қай мәтінде айтылған* + *мақтау ма, сын ба* +
*деңгейі*.

> Батырды тек мақтаудан құралған етіп көрсету — дереккөзді бұрмалау. Үмбетейдің
> өзі Бөгенбайды барымташы деп сынайды. Екі жағы да жиналады.

## Машинаға оқылатын қабат

Проза беттерінен бөлек, `data/` бумасында құрылымдық жазбалар жүреді:

| Файл | Не | Көлемі |
|---|---|---|
| `data/zhyraular.yaml` | Жыраулар, `zhyraular-tizimi.md`-ден автоматты түрде | 64 жазба, **бәрі C деңгей** |
| `data/batyrlar.yaml` | Батырлар, тексерілген деңгейлерімен | 5 жазба |

**Неге YAML.** Проза оқуға жақсы, бірақ сұраныс жасауға жарамайды. «Тип З, деңгейі
A, сын сипаттамасы бар бәрін көрсет» деген сұрақ енді бір жолмен шешіледі.

### Тексергіш — схема қағазда қалмауы үшін

`pipeline/normalize/tizilim_check.py` схемадағы ережелерді **кодпен мәжбүрлейді**:

| Ереже | Не тексеріледі |
|---|---|
| Деңгейсіз дерек жарамсыз | `dates`, `clan` өрістерінде `level` бар ма, A–E ішінде ме |
| **§4 — қасиет факт емес** | әр `trait` жазбасында `attributed_in` **және** `kind` (мақтау/сын/бейтарап) бар ма |
| Тип бүтіндігі | `З` типінде жырау көрсетілген бе; `Ж`/`Э` типінде көрсетілмеген бе |
| Сілтеме бүтіндігі | `zhyrau_ids`, `companions` шынымен тізілімде бар ма |
| «Зерттелген» мәртебесі | `primary_sources` бос емес пе, I не III деңгей дерегі бар ма |
| **Біржақтылық** | тұлғада **тек мақтау** сипаттамасы болса — ескерту береді |

Соңғы жол маңызды: ол жобаның қағидасын автоматты түрде қорғайды. Батырды тек
мақтаудан құралған етіп жазсаң, тексергіш соны көрсетеді.

Іске қосу:

```
python3 -I pipeline/normalize/tizilim_check.py
```
